CS 300 Portfolio Reflection

What Problem Was I Solving?

  In CS 300, I worked on problems involving data structures and algorithms to organize, manage, and process information efficiently. In Project One, I analyzed the runtime and memory usage of different data structures to understand their advantages and disadvantages. In Project Two, I developed a program that organizes and prints courses in the Computer Science program in alphanumeric order. The program also needed to handle course information in a way that would make it easier for users to find and review specific courses.

How Did I Approach the Problem?

  I approached these projects by comparing different data structures and considering how each one could be used to solve a particular problem. I learned that data structures are important because they influence how information is stored, accessed, searched, and organized. For example, vectors are useful for storing collections of data, hash tables can provide efficient lookups, and binary search trees can organize information for searching and traversal. I also considered Big O notation to understand how the runtime and memory requirements of different approaches could affect program performance.

How Did I Overcome Roadblocks?

  While working on the projects, I focused on understanding how each data structure worked and how to apply it correctly in my code. Breaking the problems into smaller steps helped me identify potential errors and understand the logic behind each operation. I also used testing and debugging to check my program's behavior and verify that the course information was organized and displayed correctly. Reviewing the assignment requirements and examining my code helped me identify areas that needed improvement.

How Has This Project Expanded My Approach to Software Design?

  These projects helped me understand that software design involves more than simply making a program work. It is also important to choose data structures and algorithms that fit the problem and use resources efficiently. By analyzing runtime and memory usage, I learned to consider performance before selecting an implementation. I now understand the importance of evaluating different solutions and choosing an approach that balances efficiency, functionality, and the needs of the user.

How Has My Approach to Maintainable, Readable, and Adaptable Programs Evolved?

  My work in CS 300 improved my understanding of writing code that is organized, readable, and easier to maintain. Using clear variable names, consistent formatting, and logical program structure makes code easier to understand and troubleshoot. I also learned that selecting an appropriate data structure can make a program easier to modify as requirements change. In the future, I will continue to focus on writing reusable code, testing my solutions, and documenting important decisions so that my programs can be understood and improved by other developers.
